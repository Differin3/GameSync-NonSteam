# Макеты интерфейса GameSync

Статичные макеты в стиле Steam Deck (1280×800), собранные из реальных экранов плагина
плюс концепт значка на странице non-Steam игры.

## Скриншоты

| Файл | Что показано |
|---|---|
| `shots/01-qam.png` | Боковое меню Decky (QAM) с открытым плагином |
| `shots/02-settings-main.png` | Настройки → Основные (выбор хранилища и проверка) |
| `shots/03-settings-paths.png` | Настройки → Пути игр |
| `shots/04-settings-stats.png` | Настройки → Статистика |
| `shots/06-settings-backups.png` | Настройки → Бэкапы |
| `shots/07-restore-confirm.png` | Подтверждение восстановления |
| `shots/05-game-page.png` | Концепт: страница non-Steam игры со значком и блоком GameSync |

## Исходники

- `styles.css` — общая тема (цвета Steam, панели, строки настроек);
- `qam.html` — боковое меню;
- `settings-main.html`, `settings-paths.html`, `settings-stats.html` — вкладки настроек;
- `game-page.html` + `art.svg` — страница игры с артом;
- `index.html` — галерея всех макетов (открыть в браузере).

Макеты статические: это не работающий плагин, а визуальная спецификация.
Экраны 1–4 повторяют то, что уже реализовано в `src/`, экран 5 — предложение
по доработке.

## Что нужно для экрана 5 (значок на странице игры)

Экран 5 сейчас — концепт. Чтобы он стал настоящим, плагину нужно:

1. определить, что открыта страница non-Steam игры (Steam-ярлык из `shortcuts.vdf` уже
   разбирается в `backend/steam_shortcuts.py` — там есть appid и название);
2. вставить свой элемент в страницу игры через патч библиотеки Decky
   (`routerHook` / `appDetailsPageClasses`, паттерн `findModuleExport` + `createElement`);
3. взять статус из бэкенда: последняя синхронизация и размер лежат в
   `~/.config/gamesync/synced_games.json` — новый RPC-метод отдал бы их одним вызовом;
4. по нажатию открывать настройки плагина на вкладке «Пути игр» (событие
   `gamesync-switch-tab` уже используется в текущем коде).

Значок на плитке библиотеки — отдельная, более хрупкая инъекция (патч карточек
библиотеки); его стоит делать после того, как заработает блок на странице игры.

## Как реализовано восстановление (экраны 6–7)

Сейчас плагин только загружает архив; `download_file` и `extract_backup` в бэкенде
реализованы, но нигде не вызываются. Чтобы «Бэкапы» заработали:

1. новый RPC-метод списка бэкапов: пройти по `provider.list_files("GameSync")`
   и сопоставить имена архивов с играми из `synced_games.json`;
2. метод восстановления: `create_backup` текущих сейвов (резерв) → `provider.download_file`
   → `extract_backup` с проверкой путей (защита от Zip Slip) → запись файлов в `drive_c`;
3. хранить историю версий (последняя + N предыдущих) — сейчас имя архива стабильное,
   и новая синхронизация перезаписывает облачную копию;
4. на фронтенде — вкладка «Бэкапы» с подтверждением и прогрессом, событие
   `gamesync-switch-tab` уже поддерживает переключение вкладок.

История версий раскладывается по папкам `GameSync/<Игра>/backup-<дата>.tar.gz`;
индекс — `~/.config/gamesync/backups.json`. Подробности — в `docs/ARCHITECTURE.md`.
